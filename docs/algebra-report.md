## 1. The paints

A paint is the set of primaries in it, so there are exactly eight. With Mix, Filter and Invert they form a Boolean algebra (the subsets of {red, yellow, blue}); Shift is one of its symmetries.

| Paint | Primaries | Opposite (Invert) | Shifted |
|---|---|---|---|
| White | none | Black | White |
| Red | red | Green | Yellow |
| Yellow | yellow | Purple | Blue |
| Orange | red, yellow | Blue | Green |
| Blue | blue | Orange | Red |
| Purple | red, blue | Yellow | Orange |
| Green | yellow, blue | Red | Purple |
| Black | red, yellow, blue | White | Black |

Laws the pieces obey, each checked on every combination of paints. Puzzles can lean on them; several levels are one law in disguise.

- ✓ Order doesn't matter: Mix(a, b) = Mix(b, a), and the same for Filter.
- ✓ Grouping doesn't matter: Mix(Mix(a, b), c) = Mix(a, Mix(b, c)), and the same for Filter. So a Mix or Filter of any number of paints is well defined.
- ✓ Doubling changes nothing: Mix(a, a) = Filter(a, a) = a.
- ✓ White changes nothing in a Mix and wipes out a Filter; Black changes nothing in a Filter and fills a Mix.
- ✓ Absorption: Mix(a, Filter(a, b)) = a and Filter(a, Mix(a, b)) = a.
- ✓ Each spreads over the other: Filter(a, Mix(b, c)) = Mix(Filter(a, b), Filter(a, c)), and with Mix and Filter swapped.
- ✓ Opposites: Invert(Invert(a)) = a; Mix(a, Invert(a)) = Black; Filter(a, Invert(a)) = White.
- ✓ De Morgan: Invert(Mix(a, b)) = Filter(Invert(a), Invert(b)) and Invert(Filter(a, b)) = Mix(Invert(a), Invert(b)). (Keep What They Share and Mix Without Mix.)
- ✓ Three Shifts make a full turn: Shift(Shift(Shift(a))) = a. Two Shifts turn the wheel back one step.
- ✓ Shift leaves only White and Black as they are.
- ✓ Shift respects the other pieces: Shift(Mix(a, b)) = Mix(Shift(a), Shift(b)), the same for Filter, and Shift(Invert(a)) = Invert(Shift(a)). (So without a pot nothing can tell the primaries apart.)
- ✓ Mix can't be undone: Mix(a, b) = Mix(a, c) doesn't mean b = c (Mix(Red, Orange) = Mix(Red, Yellow)). Neither can Filter (Filter(Red, Orange) = Filter(Red, Purple)). Invert and Shift can: different paints in, different paints out.

## 3. The base kit: NOR, Shift and one Red pot

NOR is Invert after Mix, as a single vat. The argument that these three build any machine, whatever its number of inputs:

1. **Pots:** White = NOR(Red, NOR(Red, Red)). Yellow = Shift(Red), Blue = Shift(Yellow). Any color is a Mix of those.
2. **Paint logic within each primary:** NOR alone builds Invert, Mix and Filter, applied to each primary separately.
3. **Moving paint between primaries:** "Any Red?" = Filter(x, Red), then Mix it with its Shift and its double Shift. The result is Black if x has red, White if not. Same for yellow and blue.
4. **Any machine:** for every input combination that should give paint, test "is input 1 exactly this color, input 2 exactly that color, ..." with the step-3 answers and Filter, keep the wanted color with Filter, and Mix all those terms together.

The checker builds every step from real pieces and runs them on every possible input, then does the same for whole random machines (section 5).

## 4. Candidate starting kits

The game's kit (DESIGN.md 2.5) is Red pot, Mix, Filter, Invert and Shift: complete, since it holds the second kit below.

| Kit | Verdict | Why |
|---|---|---|
| NOR + Shift + Red pot | **Complete** | The base kit itself. |
| Mix + Invert + Shift + Red pot | **Complete** | NOR = Invert after Mix. |
| Mix + Filter + Invert + Shift + Red, Yellow, Blue pots | **Complete** | NOR = Invert after Mix. |
| Mix + Filter + Contrast + Shift + Red pot | **Complete** | Black = Red + Shift(Red) + Shift(Shift(Red)); NOR = Contrast of the Mix with Black. |
| NOR + Shift, no pot | Incomplete | *Blind to the wheel's turn.* Every piece behaves the same if red, yellow and blue are all turned one step around the wheel. Nothing built from them can single out one primary, so a Red pot can't be built. |
| NOR + Red pot, no Shift | Incomplete | *Red stays in its lane.* Whether an output has red depends only on whether the inputs have red. Paint never moves between primaries, so Shift can't be built. |
| Mix + Filter + Invert + Shift, no pots | Incomplete | *Blind to the wheel's turn.* Every piece behaves the same if red, yellow and blue are all turned one step around the wheel. Nothing built from them can single out one primary, so a Red pot can't be built. |
| Mix + Filter + Shift + 3 pots, no Invert | Incomplete | *Only adds paint.* Every piece gives the same or more paint when its inputs get more paint. Nothing built from them can take paint away, so Invert can't be built. |
| Mix + Filter + Invert + 3 pots, no Shift | Incomplete | *Red stays in its lane.* Whether an output has red depends only on whether the inputs have red. Paint never moves between primaries, so Shift can't be built. |
| Mix + Filter + Invert + Swap red/yellow + 3 pots | Incomplete | *Blue stays in its lane.* Whether an output has blue depends only on whether the inputs have blue. Blue can never move into another primary, so Shift can't be built. |
| Contrast + Shift + Red pot, no Mix or Filter | Incomplete | *Only toggles.* Every piece works like Contrast: it only ever toggles primaries on and off. Toggles only combine into more toggles, so Filter and Mix can't be built. |

## 7. Future work

Not decided: candidates for the designer, grouped by the families of DESIGN.md 2.3 and by what logic design calls them.

### 7.1 Candidate pieces today's rules can build

Each is a plain function of its inputs, so it could be an invention level today; pieces with two or more outputs need an invention level with more than one loom first (7.2). Priced in the game's kit, the same way as section 6. Questions answer Black for yes and White for no, the form an If White brancher (7.2) would read.

| Family | Candidate | In -> out | What it does | Game kit | Cheapest machine |
|---|---|---|---|---|---|
| Questions | Any Paint? | 1 -> 1 | Black if the paint isn't white, otherwise White. | **4** | `Mix(Mix(A, Shift(A)), Shift(Shift(A)))` |
| Questions | Is It White? | 1 -> 1 | Black if the paint is white, otherwise White. The condition an If White brancher reads. | **5** | `Filter(Filter(Invert(A), Shift(Invert(A))), Shift(Shift(Invert(A))))` |
| Questions | Is It Black? | 1 -> 1 | Black only if the paint is black. | **4** | `Filter(Filter(A, Shift(A)), Shift(Shift(A)))` |
| Questions | Odd Paint? | 1 -> 1 | Black if the paint has one or three primaries (a primary or black). | 7–10 | hand-built: 10 (4 Filter, 2 Invert, 2 Mix, 2 Shift) |
| Questions | Contains? | 2 -> 1 | Black if the first paint has every primary of the second. | **6** | `Filter(Filter(Mix(A, Invert(B)), Shift(Mix(A, Invert(B)))), Shift(Shift(Mix(A, Invert(B)))))` |
| Counting | Settle | 1 -> 1 | Keeps how much paint, drops which: none White, one primary Red, two Orange, three Black. | 7–15 | hand-built: 15 (6 Mix, 5 Filter, 3 Shift, 1 Red pot) |
| Counting | Darker? | 2 -> 1 | Black if the first paint has more primaries than the second. | 6–33 | hand-built: 33 (13 Mix, 11 Filter, 7 Shift, 1 Invert, 1 Red pot) |
| Wheel | Turn Back | 1 -> 1 | Turns the wheel one step the other way. | **2** | `Shift(Shift(A))` |
| Wheel | Mirror | 1 -> 1 | Swaps red and blue, keeps yellow. With Shift it makes every reordering of the primaries. | 7–11 | hand-built: 11 (5 Shift, 3 Filter, 2 Mix, 1 Red pot) |
| Paint-like | Same Paint | 2 -> 1 | The primaries both paints have or both lack. | **4** | `Mix(Filter(A, B), Invert(Mix(A, B)))` |
| Paint-like | Stencil | 3 -> 1 | Each primary from A where the stencil C has it, from B where it doesn't. | **4** | `Filter(Mix(B, C), Mix(A, Invert(C)))` |
| Choosing | Gate | 2 -> 1 | The paint B if the control A has any paint, otherwise White. | **5** | `Filter(B, Mix(Mix(A, Shift(A)), Shift(Shift(A))))` |

Logic-design names, for reference: Any Paint? is an OR of the primaries, Is It Black? an AND, Odd Paint? parity, Contains? subset (implication), Same Paint XNOR, Stencil a per-primary multiplexer, Choose a whole-paint multiplexer (if-then-else), Gate an enable, Sort a compare-exchange (the step of a sorting network), Share and Differ a half adder (carry and sum), Settle a thermometer code (popcount), Darker? a magnitude comparator.

### 7.2 What today's rules can't build

With one-drop tubes every piece takes one drop per input and gives one per output, and a loop waits on itself, so every machine weaves stitch i from the cards' i-th drops: a pure function. That is what lets the solver prove star counts and an invention run as a one-tick lookup. Four families need more:

| Family | Logic ancestor | Smallest new piece | Rule change | What it opens up |
|---|---|---|---|---|
| **Memory** | D flip-flop, register | **Delay** (1 -> 1): gives the drop it got last time; starts holding a preset paint (White, or one the player taps in) | None to the firing rule: it fires like any one-input piece and starts with a drop in its output tube (an initial token, as in synchronous dataflow). A loop becomes legal when it passes through a Delay. An invention with Delays becomes a state table (state and inputs to new state and output); the every-paint check covers every state. | Toggle (Invert in a loop: alternates), ring counter (Shift in a loop: red, yellow, blue), running Mix (everything so far), change detector (Contrast of a drop and the one before), Keeper (a register: Stencil fed back through a Delay, written where the enable has paint), rows that grow from the row before (cellular automata, DESIGN.md 5.5). Combinational pieces plus Delays build every finite-state machine. |
| **Branching** | Demultiplexer, conditional jump | **If White** (2 -> 2): a control drop and a paint drop; the paint leaves by the top exit if the control is white, by the bottom otherwise, and the other exit gets nothing. Wired with the same drop on both inputs, a drop routes itself. | A piece fires when the exit it will use is free. Stitch i no longer comes from the cards' drop i, so the solver needs a stream model and an invention must record which exit fires. Needs **Merge** (2 -> 1, oldest drop first, top on ties) and the Catch pot back as a bin. | Removing smudges instead of recoloring them, sorting streams, dedupe, counting, buffer puzzles (DESIGN.md 5.4). The Questions in 7.1 become its conditions. |
| **Register-like cards** | Register file, FIFO, delay-line memory | **Slate** (1 -> 1): a card with an input port; the machine writes drops in on its left and reads them out in order on its right. It can start blank or with paint. | A card that can be written, and a loom or level that waits for it. | Two-pass machines, reversing a row, the Jacquard card chain as a loop of cards (a long delay), output cards a later level reads back. |
| **Several outputs** | Multi-output blocks (decoders, adders) | An invention level with two or three looms; each loom becomes an output port, in loom order | Today an invention has exactly one output (`core/pieces.gd` ports). | Prism, Sort, Share and Differ, the Three-way Switch. |
